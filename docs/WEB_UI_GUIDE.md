# 🎨 Web 可视化界面使用指南

## 📋 功能特性

### 实时监控
- **3D 点云显示**: 实时渲染点云数据，支持旋转、缩放
- **检测结果**: 显示当前检测到的人数和摔倒状态
- **报警通知**: 即时显示摔倒报警信息
- **性能监控**: FPS、处理时间等实时指标

### 统计图表
- **FPS 趋势图**: 查看系统处理速度变化
- **处理时间图**: 监控单帧处理耗时
- **报警统计**: 确认摔倒 vs 疑似摔倒分布

### 报警历史
- **历史记录**: 查看所有报警事件
- **过滤查询**: 按报警级别筛选
- **数据导出**: 导出 CSV 格式报警记录

### 数据管理
- **数据集列表**: 查看已录制的数据集
- **配置管理**: 导入/导出系统配置
- **参数调整**: 实时调整检测参数

## 🚀 快速启动

### 方法 1: 使用启动脚本（推荐）

```bash
cd /root/.openclaw/workspace/projects/fall-detection-system

# 赋予执行权限
chmod +x start.sh

# 运行启动向导
./start.sh
```

然后选择选项 `1) 🎨 Web 界面 (Streamlit)`

### 方法 2: 手动启动

```bash
cd /root/.openclaw/workspace/projects/fall-detection-system

source venv/bin/activate
```

## 🎛️ 界面说明

### 侧边栏 - 控制面板

#### 系统控制
- **▶️ 启动**: 开始实时检测
- **⏹️ 停止**: 暂停检测
- **🔄 重置**: 清空所有数据和状态

#### 参数配置
可以实时调整以下参数：

| 参数 | 说明 | 默认值 | 范围 |
|------|------|--------|------|
| 体素尺寸 | 点云降采样精度 | 0.05m | 0.01-0.2m |
| 高度骤降阈值 | 触发摔倒的高度变化 | 0.3m | 0.1-1.0m |
| 速度阈值 | 触发摔倒的下落速度 | 0.5m/s | 0.2-2.0m/s |
| 确认帧数 | 连续多少帧确认摔倒 | 2 | 1-10 |
| 帧率 | 系统运行帧率 | 30 FPS | 10-60 FPS |

**提示**: 
- 调低阈值会更敏感（更多报警，可能误报）
- 调高阈值会更严格（更少报警，可能漏报）
- 修改后点击"💾 保存配置"
- 如果系统正在运行，会自动重启应用新配置

#### 系统信息
- **运行时长**: 系统已运行时间
- **总报警数**: 累计报警次数
- **平均 FPS**: 平均处理速度
- **活跃追踪**: 当前追踪的人数

---

### Tab 1: 📊 实时监控

#### 状态指示器
- **系统状态**: 🟢 运行中 / 🔴 已停止
- **当前人数**: 实时检测到的人数
- **确认摔倒**: 已确认的摔倒次数
- **疑似摔倒**: 待确认的摔倒次数

#### 点云视图
- **3D 可视化**: 使用 Plotly 渲染点云
- **颜色映射**: 根据高度显示不同颜色
- **坐标轴**: X/Y/Z 轴范围自动调整
- **交互**: 支持鼠标旋转、缩放、平移

#### 检测结果面板
- **当前帧 ID**: 正在处理的帧
- **检测到人数**: 当前帧人数
- **摔倒状态**: ⚠️ 检测到摔倒 / ✅ 正常
- **处理时间**: 单帧处理耗时（毫秒）
- **最近报警**: 显示最近 5 条报警

---

### Tab 2: 📈 统计图表

#### FPS 趋势图
- 显示最近 100 帧的处理速度
- 蓝色线条表示 FPS 变化
- 理想值：> 20 FPS

#### 处理时间图
- 显示最近 100 帧的处理耗时
- 绿色线条表示时间变化
- 理想值：< 100ms

#### 报警统计
- **确认摔倒**: 红色计数
- **疑似摔倒**: 橙色计数
- **饼图**: 报警类型分布

---

### Tab 3: 📋 报警历史

#### 报警列表
显示所有报警事件的详细信息：

| 列名 | 说明 |
|------|------|
| 时间 | 报警发生时间 |
| 类型 | fall_confirmed / fall_suspected |
| 人员 ID | 检测到摔倒的人员编号 |
| 消息 | 报警详细描述 |
| 置信度 | 算法置信度（0-100%） |
| 级别 | critical / warning |

#### 过滤功能
- **全部**: 显示所有报警
- **确认摔倒**: 只显示 confirmed
- **疑似摔倒**: 只显示 suspected

#### 导出功能
- 点击"📥 导出 CSV"按钮
- 下载包含所有报警记录的 CSV 文件
- 可用于后续分析和报告

---

### Tab 4: 📁 数据管理

#### 数据集列表
- 自动扫描 `datasets/` 目录
- 显示每个数据集的信息：
  - 名称
  - 帧数
  - 时长
  - 创建时间
- 点击"📂 查看"显示数据集路径

#### 配置管理
- **💾 导出配置**: 保存当前配置到 `config.json`
- **📥 导入配置**: 从 `config.json` 加载配置
- **当前配置**: 以 JSON 格式显示当前所有参数

## ⚙️ 配置说明

### 推荐配置（老年人场景）

```json
{
  "voxel_size": 0.05,
  "height_drop_threshold": 0.3,
  "velocity_threshold": 0.5,
  "confirmation_frames": 2,
  "fps": 30
}
```

**特点**: 较敏感，快速响应，适合高风险场景

### 推荐配置（儿童场景）

```json
{
  "voxel_size": 0.05,
  "height_drop_threshold": 0.5,
  "velocity_threshold": 1.0,
  "confirmation_frames": 5,
  "fps": 30
}
```

**特点**: 较严格，减少误报，适合活泼好动场景

### 推荐配置（高性能场景）

```json
{
  "voxel_size": 0.1,
  "height_drop_threshold": 0.4,
  "velocity_threshold": 0.8,
  "confirmation_frames": 3,
  "fps": 60
}
```

**特点**: 降低点数提高速度，适合实时性要求高的场景

## 🐛 常见问题

### Q1: 浏览器没有自动打开？

**A**: 手动访问 http://localhost:8501

### Q2: 端口被占用？

**A**: 使用其他端口启动：
```bash
streamlit run app.py --server.port 8502
```

### Q3: 点云显示空白？

**A**: 
1. 检查是否点击了"▶️ 启动"
2. 检查相机连接（如果使用真实相机）
3. 尝试点击"🔄 重置"

### Q4: FPS 很低怎么办？

**A**:
1. 增大体素尺寸（如 0.1）
2. 降低帧率设置
3. 减少点云分辨率
4. 关闭其他占用 CPU 的程序

### Q5: 误报太多怎么办？

**A**:
1. 增加高度骤降阈值
2. 增加速度阈值
3. 增加确认帧数
4. 调整地面分割参数

### Q6: 漏报怎么办？

**A**:
1. 降低高度骤降阈值
2. 降低速度阈值
3. 减少确认帧数
4. 检查相机角度和位置

## 📊 性能指标

### 理想性能
- **FPS**: > 20
- **处理时间**: < 100ms
- **准确率**: > 95%
- **误报率**: < 5%

### 影响因素
- **硬件性能**: CPU/GPU 速度
- **点云密度**: 点数越多越慢
- **参数设置**: 体素大小影响最大
- **相机帧率**: 30 FPS vs 60 FPS

---

## 💡 使用技巧

1. **先模拟后真实**: 先用模拟数据熟悉界面，再连接真实相机
2. **参数微调**: 每次只调整一个参数，观察效果
3. **记录配置**: 找到好的参数后立即导出配置
4. **定期清理**: 报警历史过多时重置系统
5. **性能优先**: 如果卡顿，优先降低体素精度
